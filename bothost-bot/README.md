# RadarMap Telegram Bot для BotHost

Бот получает новые события с `https://radar-map.ru` и отправляет их пользователям,
которые открыли бота и отправили `/start`.

## Загрузка на BotHost

1. Загрузите содержимое этой папки в отдельный GitHub/GitLab-репозиторий.
2. На BotHost создайте новый Telegram-бот.
3. Вставьте токен BotFather в поле **Bot Token**.
4. Укажите Git URL этого репозитория и ветку `main`.
5. Выберите Python и главный файл `app.py`.
6. Используйте long polling, webhook для этого бота не нужен.

В репозитории уже есть `app.py`; запуск выполняется командой `python app.py`.
Дополнительные библиотеки и база данных не требуются.

## Переменные окружения

BotHost обычно передаёт токен из поля **Bot Token**. Код также принимает
переменные `TELEGRAM_BOT_TOKEN`, `BOT_TOKEN`, `TELEGRAM_TOKEN` или `TOKEN`.

Не добавляйте токен в Git-репозиторий и не записывайте его в исходный код.

Необязательные переменные:

- `RADAR_MAP_API_URL` — адрес источника, по умолчанию `https://radar-map.ru/api/state`;
- `RADAR_MAP_POLL_INTERVAL_MS` — интервал проверки в миллисекундах, по умолчанию `15000`.
- `RADAR_SUBSCRIBERS_FILE` — путь к постоянному файлу подписчиков. По умолчанию
  используется `bothost-bot/data/subscribers.json`, который не перезаписывается
  обновлением кода из Git.
- `SUPABASE_URL` и `SUPABASE_KEY` — постоянное хранилище подписчиков в Supabase.
  При их наличии бот использует таблицу `radarmap_subscribers`, а локальный файл
  остаётся резервной копией.

На BotHost должна сохраняться папка `bothost-bot/data/` между перезапусками.
Если BotHost предоставляет постоянный каталог, укажите его через
`RADAR_SUBSCRIBERS_FILE`.

Для Supabase выполните SQL из `supabase_schema.sql`. Для серверного бота
используйте `service_role` key только через Secrets, не добавляйте его в Git.

## Команды пользователя

- `/start` — подписаться;
- `/stop` — отписаться;
- `/help` — показать команды.
- `/map` — получить фото живой карты RadarMap.
